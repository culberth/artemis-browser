artemis-browser {{ .Chart.AppVersion }} is installed as "{{ .Release.Name }}" in {{ .Release.Namespace }}.

{{- if .Values.ingress.enabled }}

  1. The hostname has to resolve to your ingress controller. On KinD that means a hosts entry
     (C:\Windows\System32\drivers\etc\hosts, as Administrator):

         127.0.0.1 {{ .Values.ingress.host }}

{{- $tlsSecret := .Values.ingress.tls.secretName }}
{{- if and $tlsSecret (lookup "v1" "Secret" .Release.Namespace $tlsSecret) }}

  2. Then open:  https://{{ .Values.ingress.host }}/

     The ingress serves the certificate in secret {{ $tlsSecret }} and redirects HTTP to HTTPS;
     it talks HTTPS to the pod as well.
{{- else }}

  2. Then open:  http://{{ .Values.ingress.host }}/

     That last hop is plain HTTP: secret {{ $tlsSecret | default "(ingress.tls.secretName unset)" }}
     does not exist, so the ingress has no certificate for the browser. The pod itself serves
     HTTPS; the browser-to-ingress hop is not encrypted. For HTTPS there, run
     scripts/new-tls-secret.ps1 and upgrade once.
{{- end }}
{{- else }}

  No ingress was installed. Reach it with a port-forward:

      kubectl port-forward -n {{ .Release.Namespace }} svc/{{ .Release.Name }} 8443:8443

  Then open https://localhost:8443/ and accept the self-signed certificate.
{{- end }}

  Sign in as "{{ .Values.auth.username }}" with the password whose hash you passed in.

{{- if .Values.broker.seedConnection }}

  The connect page already lists "{{ .Values.broker.label }}"
  ({{ .Values.broker.host }}:{{ .Values.broker.port }} as {{ .Values.broker.username }}).
  Broker passwords are never stored, so you type that one each session.
{{- end }}
