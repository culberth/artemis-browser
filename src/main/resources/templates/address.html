Filters are Artemis core syntax — AMQPriority, AMQTimestamp, or a property by its bare name. A JMS selector given when subscribing is stored already translated, so JMSPriority > 3 shows here as AMQPriority > 3. A filtered subscription is meant to receive fewer messages than the others; a lower Added is not lag.

Oldest undelivered is how long the oldest message not yet handed to a consumer has waited, which means the same thing on every subscription whatever its filter — so it, not a count, decides which subscriber is furthest behind. Messages delivered and awaiting acknowledgement are not counted in it: the broker reports no age for them.

The broker names a subscription's queue after how it was made — clientId.subscription for a durable one — so client and subscription are split from that name. (from the name) marks a split no attached consumer has confirmed; a queue configured on the broker can have a dot in its name for its own reasons. A non-durable subscription goes away when its consumer disconnects.

Which subscriptions hold a message?

Every subscription on this address is searched, and each says whether it holds a match — which answers did subscriber B get it? without guessing from counters. Core syntax, as above. A search only sees messages still waiting: one delivered to a consumer and not yet acknowledged, or one scheduled for later, cannot be browsed, so where a subscription has either, “not found” is not a clean no.
